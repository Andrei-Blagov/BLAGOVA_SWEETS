## Производственная вместимость

Сервер использует структурированные снимки и производственную нагрузку. Общий бюджет и пределы категорий проверяются одновременно, под блокировкой даты в одной транзакции. Состояние занятости учитывает всю БД, а не страницу админки.

Правила первой версии используют одновременно общий бюджет интервала и пределы категорий:

| Производственная сущность | Нагрузка | Предел на интервал |
| --- | ---: | ---: |
| Торт | 8 единиц | 4 торта |
| Набор конфет | 4 единицы | 4 набора |
| Комплект подарочных пряников | 1 единица | 8 комплектов |
| Капкейк или трайфл | 1 единица за штуку | 32 штуки суммарно на старте |

- Общий бюджет одного интервала: 32 единицы нагрузки.
- Эквивалентность: 8 капкейков/трайфлов = 1 торт = 2 набора конфет = 8 комплектов пряников.
- Минимальное количество капкейков/трайфлов в позиции: 1 штука.
- Заказ принимается, только если после его добавления не превышены общий бюджет и каждый категорийный предел.
- Примеры допустимых наборов: 2 торта + 2 набора конфет + 1 комплект пряников; 3 торта + 1 набор конфет + 1 комплект пряников; 1 торт + 3 набора конфет + 2 комплекта пряников.
- Праздничный или подарочный комплект расходует сумму нагрузки входящих компонентов. Для нестандартной позиции менеджер задаёт нагрузку вручную.
- Коэффициенты, общий бюджет и категорийные пределы редактируются владельцем в админке и сохраняются с версией.
- Availability API принимает состав корзины и возвращает, помещается ли именно этот состав в интервал.
- Подтверждение и перенос выполняют повторную транзакционную проверку под advisory lock.
- Pending-заявки с определённым составом удерживают место 60 минут по `reservation_expires_at`; срок настраивает владелец. Истечение освобождает ресурс без изменения статуса. Позднее подтверждение повторно проверяет вместимость.
- Решения владельца 05.10: подарки считают конфеты наборами по 6, пряники комплектами по 2; округление вверх по каждой категории внутри одного подарка, затем умножение на количество подарков. Праздничный комплект содержит один торт, выбранные капкейки по одному на гостя, пряники комплектами по 2 с округлением вверх.
- Неполная заявка из чата сохраняется без резерва. Перед подтверждением staff задаёт ненулевые категории нагрузки, основание оценки и согласованную цену для заявки без позиций. Нулевая/неизвестная нагрузка не допускается при подтверждении.
- Исторические 9 demo-заказов и 18 позиций сохранены без попыток восстановить утраченную конфигурацию. NULL означает неизвестную нагрузку; pending требует оценки. Подтверждённый заказ с неизвестной нагрузкой блокирует новые бронирования на пересекающееся время.
- Изменение правил создаёт новую строку `production_rule_versions` с автором и временем. Подтверждённые снимки и нагрузка не пересчитываются; новые пределы применяются при позднем подтверждении и переносе.
- Для обычных вариантов структурированный состав хранится в `production_variant_profiles`, редактируется владельцем и аудируется; у вариантов капкейков по 6 штук нагрузка равна 6 на позицию. Новый вариант должен иметь явный профиль.
- Блокировки дат шире блокировки одного интервала: пересечения при изменённом расписании и переносы между двумя датами защищены; даты блокируются в стабильном порядке. Идемпотентность создания защищена отдельной блокировкой request_key.

## Бюджет и AI

- Разработка ведётся в пределах ChatGPT Plus. При исчерпании лимита создаётся точный handoff-промпт для Cursor.
- Для автоматического AI на сайте у владельца есть отдельный оплачиваемый OpenAI API аккаунт.
- Первый тестовый этап: рабочая база знаний, поиск только по опубликованным материалам, ссылки на источники и передача менеджеру. Генеративный ответ на сайте пока не включается.
- Следующий отдельный этап: OpenAI Responses API за серверным модулем, модель и лимиты через конфигурацию, журналирование источников, оценочный набор вопросов и безопасный fallback к менеджеру.
- LINE Official Account ещё не создан. Входящие LINE и ответы менеджера из LINE — поздний этап.
- Производственный календарь Supabase остаётся источником истины. Google Calendar можно добавить позднее как синхронизируемое представление, если появится рабочая необходимость.
