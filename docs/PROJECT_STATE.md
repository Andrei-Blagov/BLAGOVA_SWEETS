## Производственная вместимость

Текущая реализация считает число заказов и ограничивает интервал четырьмя заказами. Это временная модель, которую нужно заменить.

Целевая модель использует одновременно общий бюджет интервала и пределы категорий:

| Производственная сущность | Нагрузка | Предел на интервал |
| --- | ---: | ---: |
| Торт | 8 единиц | 4 торта |
| Набор конфет | 4 единицы | 4 набора |
| Комплект подарочных пряников | 1 единица | 8 комплектов |
| Капкейк или трайфл | 1 единица за штуку | 32 штуки суммарно на старте |

- Общий бюджет одного интервала: 32 единицы нагрузки.
- Эквивалентность: 8 капкейков/трайфлов = 1 торт = 2 набора конфет = 8 комплектов пряников.
- Минимальное количество капкейков/трайфлов в позиции: 1 штука.
- Заказ принимается, только если после его добавления не превышены общий бюджет и каждый категорийный предел.
- Примеры допустимых наборов: 2 торта + 2 набора конфет + 1 комплект пряников; 3 торта + 1 набор конфет + 1 комплект пряников; 1 торт + 3 набора конфет + 2 комплекта пряников.
- Праздничный или подарочный комплект расходует сумму нагрузки входящих компонентов. Для нестандартной позиции менеджер задаёт нагрузку вручную.
- Коэффициенты, общий бюджет и категорийные пределы должны редактироваться владельцем в админке и сохраняться с версией.
- Availability API принимает состав корзины и возвращает, помещается ли именно этот состав в интервал.
- Подтверждение и перенос выполняют повторную транзакционную проверку под advisory lock.
- Для ожидающих подтверждения заявок нужно добавить временное резервирование с expires_at; срок удержания сделать настройкой. До реализации точное значение не считать утверждённым.

## Бюджет и AI

- Разработка ведётся в пределах ChatGPT Plus. При исчерпании лимита создаётся точный handoff-промпт для Cursor.
- Для автоматического AI на сайте у владельца есть отдельный оплачиваемый OpenAI API аккаунт.
- Первый тестовый этап: рабочая база знаний, поиск только по опубликованным материалам, ссылки на источники и передача менеджеру. Генеративный ответ на сайте пока не включается.
- Следующий отдельный этап: OpenAI Responses API за серверным модулем, модель и лимиты через конфигурацию, журналирование источников, оценочный набор вопросов и безопасный fallback к менеджеру.
- LINE Official Account ещё не создан. Входящие LINE и ответы менеджера из LINE — поздний этап.
- Производственный календарь Supabase остаётся источником истины. Google Calendar можно добавить позднее как синхронизируемое представление, если появится рабочая необходимость.

## Зафиксированные ограничения

- Реальные платежи не подключать до отдельного этапа с webhook, идемпотентностью и возвратами.
- Тайские тексты до запуска проверяет носитель.
- Адрес, дата открытия, зоны доставки и коммерческие сроки не выдумывать.
- Не сливать PR №1 в main без отдельного решения владельца.
- Перед коммерческим запуском обязательны security review, production hardening, мониторинг и резервное копирование.
