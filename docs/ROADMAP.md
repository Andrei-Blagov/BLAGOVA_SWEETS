# BLAGOVA SWEETS — дорожная карта

Приоритет — качество и проверяемость, жёсткого срока нет. Каждый этап завершается работающим вертикальным сценарием, тестами критичных правил и обновлением PROJECT_STATE.md.

## Как выбирать модель разработки

| Модель | Использование в проекте | Режим рассуждения |
| --- | --- | --- |
| GPT-5.6 Luna | тестовые данные, переводы-заглушки, простые компоненты, механический CRUD, документация | low/medium |
| GPT-5.6 Terra | основная Nuxt/Supabase разработка, админка, Storage, обычные интеграции и тесты | medium/high |
| GPT-5.6 Sol | архитектура, миграции с конкуренцией, RLS, платежи, безопасность, сложная отладка | high/xhigh |
| GPT-6 Astra | финальный аудит особо критичного решения, когда Sol не снимает риск | high |

Правило экономии: сначала определить критерии качества на сильной модели для критичного узла, затем выполнять повторяемые части на Terra или Luna. Не использовать Astra для обычной реализации. Локальные и облачные задачи расходуют общий лимит Plus; при его исчерпании использовать docs/CURSOR_HANDOFF.md.

Ориентиры OpenAI на 22 сентября 2026 года, которые нужно перепроверять перед бюджетным решением:

| Модель | Plus: оценка локальных сообщений за 5 часов | API input/output за 1 млн токенов |
| --- | ---: | ---: |
| GPT-6 Astra | 5–45 | $10 / $50 |
| GPT-5.6 Sol | 10–100 | $4 / $20 |
| GPT-5.6 Terra | 25–200 | $2 / $12 |

Лимиты Plus не фиксированы: на расход влияют объём контекста, рассуждение, инструменты и локальный/облачный режим; могут действовать недельные ограничения. Оплата OpenAI API для AI внутри сайта отдельна от подписки Plus.

## Этап 0.5. Постоянный тестовый стенд

Результат: проверенная ветка автоматически публикуется на `https://preview.blagovasweets.com` без изменения `main` и production-домена.

- Отдельный Compose project и каталог на VPS; контейнер не публикует host port и подключается только к существующей proxy-сети.
- Caddy завершает TLS и автоматически перенаправляет HTTP на HTTPS.
- Demo banner, `robots.txt`, meta robots и `X-Robots-Tag` запрещают воспринимать стенд как production и индексировать его.
- CI строит и проверяет image без секретов; deploy job запускается только после `verify`, только из `prototype/pattaya-atelier`, использует GitHub Environment `preview` и строгий `known_hosts`.
- Каждая версия получает image с commit SHA; предыдущая конфигурация и image сохраняются для автоматического или ручного отката.
- Runbook первого запуска, логов, повторного деплоя и отката: `docs/PREVIEW_DEPLOYMENT.md`.
- Миграции БД не являются частью deployment workflow. Edge Functions публикуются отдельно только после CORS/security-проверки.

Статус: завершён 23 сентября 2026 года. DNS и HTTPS работают; managed Preview развёрнут в `/opt/blagova-sweets-preview`; CI автоматически публикует только проверенные push из `prototype/pattaya-atelier`. Проверены demo-заказ, чат-handoff, CORS пяти Edge Functions, anti-indexing, ручной rollback-контур и работа сайта после изолированного restart контейнера. `main`, Caddy, n8n, PostgreSQL и коммерческий домен не изменялись.

Модель: Terra high для Docker/CI; Sol high для финального security review. Astra не требуется.

## Этап 5. Автоматический AI/RAG через OpenAI API

Результат: управляемый генеративный помощник поверх проверенной базы знаний.

- Серверный модуль Responses API; ключ только в secrets.
- Ответ только по разрешённым источникам, обязательные ссылки и отказ от догадки.
- Ограничения длины, rate limit, бюджет, журнал model/prompt/source/version без хранения лишних персональных данных.
- Сравнить GPT-5.6 Luna и Terra на подготовленном eval-наборе; Sol использовать как эталон для сложных примеров.
- По умолчанию начать с Luna, если она достигает утверждённого качества; переключение модели оставить конфигурацией.
- Handoff менеджеру при низкой уверенности, чувствительном запросе или просьбе пользователя.

Модель разработки: Sol high для threat model и prompt-injection review; Terra high для модуля и eval harness; Luna medium для массового прогона. Runtime-кандидат: Luna как самый дешёвый, Terra только если eval показывает значимое улучшение.

## Критерии готовности демонстрационного продукта

- Весь каталог, цены, фото, переводы и доступность управляются из /admin.
- Заказ, чат и база знаний используют Supabase как единый источник истины.
- Смешанная вместимость работает транзакционно и объяснимо показывается менеджеру.
- Клиент получает согласованные письма; сбой можно увидеть и повторить.
- Поиск базы знаний приводит к источнику и корректно передаёт менеджеру неизвестные вопросы.
- Критичные сценарии покрыты интеграционными тестами и CI.
- Демо-данные можно очистить и заменить реальными без изменения бизнес-логики.
