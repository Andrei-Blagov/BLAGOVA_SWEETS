# Доступ сотрудников на Preview

| Действие | Владелец | Менеджер |
| --- | --- | --- |
| Просмотр и обработка заказов, перенос даты | Да | Да |
| Диалоги с клиентом и календарь заказов | Да | Да |
| Черновики каталога, цены, материалы базы знаний | Да | Нет |
| Публикация контента, настройки и сотрудники | Да | Нет |

Роли хранятся в `public.staff_members`. Проверка входа использует Supabase Auth и активную запись с ролью `owner` либо `manager`. Операционные RPC проверяют роль в базе; RLS скрывает материалы и неопубликованный каталог от менеджера. Интерфейс менеджера показывает только разделы «Заказы», «Диалоги», «Календарь».

Чтобы добавить менеджера на тестовом проекте:

1. Узнать рабочий email менеджера. Пароль в чат, SQL и git не записывать.
2. В Supabase Dashboard → Authentication → Users пригласить сотрудника по этому email либо проверить существующую подтверждённую учётную запись. Аккаунт создаёт и подтверждает сам сотрудник.
3. После подтверждения email администратор БД добавляет **только этого пользователя** в `public.staff_members` с ролью `manager`, `active = true`. Перед записью сверить точный email и UUID в `auth.users`; не обновлять существующую роль владельца и не повышать любого другого пользователя.
4. Проверить вход на `/login` в отдельном профиле браузера: доступны заказы, диалоги и календарь; материалы и подключения скрыты. Проверить выход и отзыв доступа через `active = false`.

Настройка приглашений через интерфейс владельца и управление сотрудниками — отдельный этап.

Восстановление пароля (код подготовлен локально, до доставки коммита на Preview ещё не работает): `/login` → «Забыли пароль?» → письмо Supabase Auth → `/reset-password`. Auth Redirect URLs уже разрешает точный `https://preview.blagovasweets.com/reset-password`; после сохранения пароля временная сессия закрывается и сотрудник входит через `/login`. Ссылки и пароли не передавать в чат. Проверить путь на развёрнутом Preview перед отправкой письма менеджеру.
